**Продукт:** аддон Blender «Camera Preset Manager»
**Формат поставки:** расширение Blender (Extensions), `blender_manifest.toml`
**Целевая версия:** Blender 4.2 LTS и новее

## 0. Что изменилось относительно v1.0

| # | Было в v1.0 | Стало в v1.1 | Причина |
|---|---|---|---|
| 1 | `location` + `rotation_euler` в плоском списке вместе с `lens`/`dof.*` | Явное разделение на блоки `transform` (Object) и `optics`/`dof` (Camera data) | Смешение `bpy.types.Object` и `bpy.types.Camera` — источник самых частых багов (`cam.lens` вместо `cam.data.lens`) |
| 2 | `rotation_euler` | `rotation_mode` + `matrix_basis` (4×4) + `delta_matrix` | Euler не работает при `QUATERNION`/`AXIS_ANGLE`; игнорировались delta-трансформации |
| 3 | `lens` | `camera_type`, `lens`, `sensor_width`, `sensor_height`, `sensor_fit`, `shift_x/y`, `clip_start/end`, `ortho_scale`, `panorama_type` | FOV зависит от сенсора; орто- и панорамные камеры вообще не покрывались |
| 4 | Не описано | Явная политика по анимации / драйверам / констрейнтам | F-кривые и констрейнты перебивают записанные значения — пресет «не работает» без предупреждения |
| 5 | «активная камера сцены» | `camera_name` в пресете + режим ретаргета в настройках | Непонятно, к какой камере применять при нескольких камерах |
| 6 | Не описано | `bl_options = {'REGISTER','UNDO'}`, `poll()`, обработка границ индекса | Отсутствие undo и трейсбеки на пустой сцене |
| 7 | `Ctrl+Alt+1…9` на каждый пресет | Pie-меню на одну клавишу + опциональные хоткеи | `Ctrl+Alt+<цифра>` перехватывается WM на Linux и macOS; 9 биндов не масштабируются |
| 8 | «больше 9 пресетов недоступно по хоткею» | Уточнено: ограничение только для дефолтных биндов | Элемент кеймапа хранит свойства оператора — пользователь сам привяжет любой индекс |
| 9 | Нет `update`, `duplicate`, `reorder` | Добавлены | Без них список нередактируем |
| 10 | Нет настроек аддона | `AddonPreferences`: хоткеи, ретаргет, длительность перехода | Пользователь не может отключить конфликтующие бинды |
| 11 | Нет импорта/экспорта | JSON export/import | Пресеты живут в `.blend`; нужен способ переносить и шарить |
| 12 | Нет тестов | `tests/run_tests.py` (headless) | DoD должен быть проверяемым |

## 1. Назначение

Аддон хранит **полные состояния камеры** и переключает их одним действием: позиция/ориентация, оптика, DOF. UX-ориентир — Bool Tool: одно меню на одну клавишу, а не десять несвязанных кнопок.

**Сценарии:**
1. Художник ставит 4 кадра-ракурса и переключается между ними во время облёта сцены.
2. Аниматор сохраняет «крупный план» и «общий план» и переключается, не теряя настройки DOF.
3. Пользователь переносит набор пресетов в другой проект через JSON.

**Non-goals (не входит в v1.1):**
- шейк (Camera Shakify) — см. §9;
- рендер превью-миниатюр;
- плавная интерполяция оптики/DOF (плавно анимируется только трансформ);
- синхронизация с маркерами таймлайна — встроенный «Bind Camera to Markers» уже решает эту задачу, см. §9.

## 2. Модель данных

Пресет — `PropertyGroup`, хранится в `CollectionProperty` **на уровне Scene** (сохраняется в `.blend`, не требует разрешений расширения).

### 2.1. Блок `transform` — свойства **Object** (не Camera data!)

| Поле | Тип | Примечание |
|---|---|---|
| `rotation_mode` | enum | `XYZ…ZYX`, `QUATERNION`, `AXIS_ANGLE` |
| `matrix_basis` | float[16] | Локальная матрица (loc/rot/scale). Восстанавливается точно, в отличие от покомпонентной записи |
| `delta_matrix` | float[16] | Свёрнутые `delta_location` / `delta_rotation_*` / `delta_scale` |

`matrix_basis` намеренно **не включает** трансформ родителя: пресет описывает состояние самой камеры и переносим между ригами. Это зафиксировано как контракт, а не как баг.

### 2.2. Блок `optics` — свойства **Camera data** (`obj.data`)

`camera_type` (PERSP/ORTHO/PANO), `lens`, `sensor_width`, `sensor_height`, `sensor_fit`, `shift_x`, `shift_y`, `clip_start`, `clip_end`, `ortho_scale`, `panorama_type` (строкой — чтобы не ломаться при добавлении новых типов панорамы в новых версиях Blender).

`lens` без `sensor_*` не описывает кадр: FOV = f(sensor, lens, sensor_fit, aspect). Поэтому сенсор обязателен в пресете.

### 2.3. Блок `dof`

`use_dof`, `focus_distance`, `aperture_fstop`, `focus_object_name` (строка).

**Важно:** если у камеры задан `dof.focus_object`, то `focus_distance` игнорируется движком. Поэтому объект фокуса хранится по имени и разрешается через `bpy.data.objects.get()`; при отсутствии — предупреждение и фолбэк на дистанцию.

### 2.4. Метаданные

`name` (уникализируется при создании/дублировании), `camera_name` — с какой камеры снят пресет.

### 2.5. Состояние на уровне Scene

| Свойство | Назначение |
|---|---|
| `cam_presets` | коллекция пресетов |
| `cam_presets_index` | активный элемент (всегда клампится после удаления/перемещения) |
| `cam_presets_channels` | `ALL` / `TRANSFORM` / `OPTICS` / `DOF` — что применять |
| `cam_presets_keyframe` | вставлять кейфреймы вместо жёсткой установки |
| `cam_presets_smooth` | плавный переход трансформа |

## 3. Архитектура

```
camera_preset_manager/
├── __init__.py            # register/unregister, порядок, очистка
├── blender_manifest.toml  # метаданные расширения (bl_info запрещён)
├── properties.py          # PropertyGroup пресета, Scene-свойства, PRESET_FIELDS
├── utils.py               # ядро: capture/apply/риски/плавный переход
├── operators.py           # save/update/apply/delete/duplicate/move/pie
├── ui_list.py             # CAMPRESET_UL_list: фильтр, отрисовка, переименование
├── panels.py              # CAMPRESET_PT_panel (N-panel)
├── pie.py                 # CAMPRESET_MT_pie + полный список пресетов
├── keymaps.py             # keyconfigs.addon, регистрация/снос, поиск конфликтов
├── preferences.py         # AddonPreferences
└── json_io.py             # экспорт/импорт JSON
tests/
├── run_tests.py           # headless smoke/regression
├── static_check.py        # проверки без Blender
├── build.bat              # сборка .zip
└── run_tests.bat          # запуск headless-тестов
```

**Ключевое решение:** вся работа с камерой — в `utils.py` (`capture_state` / `apply_state` / `describe_risks` / `start_smooth`), операторы — тонкие обёртки. Поэтому режимы «жёстко / кейфрейм / частично / плавно» не расползаются по нескольким операторам.

**Порядок регистрации:** PropertyGroup → UIList → Menu → Operator → AddonPreferences → Panel; Scene-свойства регистрируются после классов, снимаются до `unregister_class`. Обратный порядок при выключении.

## 4. Операторы

| idname | Поведение |
|---|---|
| `cam_preset.save` | Снимает состояние `scene.camera`, создаёт пресет с уникальным именем, делает его активным. Без камеры — `WARNING` + `CANCELLED` |
| `cam_preset.update` | Перезаписывает активный пресет текущим состоянием (имя сохраняется) |
| `cam_preset.apply` | `preset_index` (default `-1` = активный из списка). Читает `channels`, `keyframe`, `smooth` из Scene. Индекс вне диапазона при явном значении → `CANCELLED`, а не «применить что попало» |
| `cam_preset.delete` | Удаляет активный, клампит индекс |
| `cam_preset.duplicate` | Копирует активный пресет, имя с суффиксом `.001` |
| `cam_preset.move` | `direction = UP/DOWN` |
| `wm.call_menu_pie` c `name="CAMPRESET_MT_pie"` | Открывает pie-меню (из панели и хоткея) |
| `cam_preset.reset_scene` | Удаляет все пресеты сцены (с подтверждением) |
| `cam_preset.export` / `cam_preset.load` | JSON, `ExportHelper`/`ImportHelper`. Id называется `load`, а не `import`, чтобы не конфликтовать с зарезервированным словом Python |

Все изменяющие операторы: `bl_options = {'REGISTER', 'UNDO'}`.

## 5. Политика по анимации, драйверам и констрейнтам

Запись значений в свойства, которые ведёт F-кривая, визуально не даёт эффекта: на следующем пересчёте depsgraph анимация вернёт свои значения. То же с `Track To` / `Follow Path` / `Child Of` и с драйверами.

Поведение аддона:

1. Перед применением выполняется `describe_risks(cam)`:
   - есть `animation_data` с `action` или драйверами → предупреждение;
   - есть констрейнты → предупреждение.
2. В обычном режиме значения всё равно применяются, но пользователь получает `WARNING` в статус-бар.
3. При включённом `cam_presets_keyframe` значения сначала устанавливаются, затем вставляются кейфреймы на текущем кадре — это штатный способ «применить пресет в анимации».
4. Плавный переход при наличии анимации не запускается (иначе таймер и F-кривые будут воевать) — вместо него жёсткое применение + предупреждение.

## 6. Интерфейс

### 6.1. N-panel

`View3D > Sidebar > Camera Presets` (`bl_space_type='VIEW_3D'`, `bl_region_type='UI'`).

Содержимое:
- блок «Target»: имя камеры, к которой будет применён пресет; при отсутствии — предупреждение;
- `Save New` / `Update` / `Pie Menu`;
- `UIList` (6 строк) с именем пресета, именем камеры и фокусным расстоянием; переименование — кликом по имени;
- крупная кнопка `Apply` + `Duplicate`;
- `Move Up` / `Move Down` / `Delete`;
- настройки: `Apply` (каналы), `Keyframe`, `Smooth`;
- подсказка по хоткеям и счётчик пресетов.

### 6.2. Pie-меню

Динамическое, рисуется в рантайме — поэтому показывает актуальный список пресетов (в отличие от статических биндов).

- до 8 пресетов по слотам;
- если пресетов больше — последний слот `All Presets (N)` открывает полный список;
- если слотов меньше 8 — оставшиеся занимают `Save New` и `Update Current`.

### 6.3. Настройки аддона

| Настройка | Default | Смысл |
|---|---|---|
| `register_keymaps` | on | Регистрировать дефолтные хоткеи (для конфликтных конфигураций) |
| `retarget_mode` | `SCENE` | Применять к активной камере сцены или к камере из пресета |
| `smooth_seconds` | `0.35` | Длительность плавного перехода трансформа |

## 7. Горячие клавиши

Регистрация в `wm.keyconfigs.addon` (не `user`), область `3D View`, регион `WINDOW`.

| Клавиши | Действие |
|---|---|
| `Ctrl+Alt+C` | Pie-меню пресетов |
| `Ctrl+Alt+S` | Save New |

**Почему не `Ctrl+Alt+1…9`:**
- на Linux (GNOME/KDE) `Ctrl+Alt+<цифра>` переключает рабочие столы — событие не доходит до Blender;
- на macOS `Ctrl+Option+<цифра>` вводит спецсимволы и часто перехватывается системой;
- 9 статических биндов не масштабируются на реальные наборы пресетов.

При регистрации выполняется поиск конфликтов в `keyconfigs.user` и `keyconfigs.default`; найденные совпадения выводятся в консоль и показываются в настройках аддона. Все бинды удаляются в `unregister()` — «мусора» в кеймапе не остаётся.

**Уточнение по индексам:** жёстко регистрируется только оператор. Элемент кеймапа хранит свойства оператора, поэтому пользователь может вручную привязать `cam_preset.apply` с `preset_index = 11` к любой клавише. Ограничение «первые девять» относится только к дефолтному набору.

## 8. Манифест, сборка, установка

`blender_manifest.toml`:

```toml
schema_version = "1.0.0"
id = "camera_preset_manager"
version = "1.1.0"
name = "Camera Preset Manager"
tagline = "Quick camera state presets with hotkeys"
maintainer = "Your Name <email@example.com>"
type = "add-on"
blender_version_min = "4.2.0"
license = ["SPDX:GPL-3.0-or-later"]

[permissions]
files = "Import and export preset libraries as JSON files"
```

Правила:
- `bl_info` в `__init__.py` **отсутствует** (формат расширений); поддержка Blender ≤4.1 — отдельная legacy-сборка, в один пакет не совмещается;
- `id` — стабильный, нижний регистр;
- `version` — semver, повышается при каждом релизе;
- `tagline` — до 64 символов;
- `[permissions] files` заявлен, потому что экспорт/импорт пишет по пути, выбранному пользователем.

Сборка и проверка (Blender 4.2+):

```bash
blender --command extension validate ./camera_preset_manager
blender --command extension build --source-dir ./camera_preset_manager --output-dir ./dist
```

Установка: `Edit > Preferences > Get Extensions > Install from Disk` (или перетащить `.zip` в окно Blender).

## 9. Ограничения и осознанные решения

- **Camera Shakify.** Состояние шейка не сохраняется: это сторонний аддон с собственной моделью данных. В документации фиксируется ограничение. Точка расширения на будущее — кастомные свойства `camera["cam_preset_ext"]`, чтобы сторонние аддоны сами дописывали своё состояние.
- **Родитель камеры.** Трансформ родителя не входит в пресет (`matrix_basis` — локальное пространство).
- **Пресеты привязаны к `.blend`.** В новом файле список пуст — это ожидаемо; перенос через JSON.
- **Плавный переход** анимирует только трансформ. Оптика и DOF применяются мгновенно: интерполяция `lens` ломает ощущение кадра сильнее, чем помогает, а `panorama_type`/`camera_type` не интерполируются вовсе.
- **Маркеры таймлайна.** Встроенный `marker.camera` + «Bind Camera to Markers» уже даёт переключение камер по времени; дублировать не нужно.
- **Undo при плавном переходе.** Первое изменение попадает в undo-стек; промежуточные кадры таймера — нет. Пресеты остаются согласованными, потому что финальное состояние применяется тем же кодом.

## 10. Тестирование и критерии готовности

`tests/run_tests.py` запускается headless:

```bash
blender --background --factory-startup --python tests/run_tests.py
```

Проверки (Definition of Done):

1. `register()` / `unregister()` / повторный `register()` без ошибок и без дублей в кеймапе.
2. Аддон ставится из `.zip` в чистый Blender 4.2+; `extension validate` проходит.
3. В N-panel есть вкладка «Camera Presets» с кнопкой сохранения и списком.
4. Сохранение/применение корректно меняет позицию, вращение, FOV и DOF.
5. Пресет с `rotation_mode='QUATERNION'` восстанавливается идентично.
6. Пресет ортокамеры восстанавливает `ortho_scale` (а не `lens`).
7. Пресет с `dof.focus_object` восстанавливает фокус на объект; при отсутствии объекта — предупреждение и `focus_distance`.
8. Применение при `scene.camera is None` и явном индексе вне диапазона не бросает исключений.
9. `Ctrl+Z` после применения возвращает предыдущее состояние.
10. При выключении аддона хоткеи удаляются из Keymap, Scene-свойства снимаются.
11. Пресеты переживают сохранение/перезагрузку `.blend`.
12. JSON export → import даёт идентичные состояния.
13. Частичное применение (`TRANSFORM` / `OPTICS` / `DOF`) не трогает остальные каналы.

**Статус проверки (Blender 5.2.3 LTS, build e13b728c6880):**

Выполнено и проходит:

- `blender --command extension validate` — манифест валиден;
- `tests/run_tests.py` — **71 проверка**, включая поведение UI-классов, валидность имён иконок, roundtrip, кватернионы, ортокамеру, DOF-объект, границы индекса, частичные каналы, кейфреймы, дублирование/перемещение, JSON, reload;
- `tests/install_check.py` — **17 проверок**: пакет устанавливается из `.zip`, включается как `bl_ext.user_default.camera_preset_manager`, настройки и пресеты работают под именем расширения;
- сборка `.zip` (11 файлов, манифест и модули в корне, без тестов и байткода).

Не проверено автоматически (требует ручного прогона в UI): фактическая отрисовка панели/pie/списка, срабатывание хоткеев на реальной раскладке, `Ctrl+Z` после применения, сохранение/перезагрузка `.blend`.

**Найдено и исправлено в ходе проверки:**

1. `unique_name()` считал сам добавляемый элемент конфликтом — при импорте JSON все имена получали суффикс `.001`. Добавлен параметр `exclude`.
2. Нумерация первого пресета начиналась с «Preset 2» (длина считалась после `add()`).
3. У экземпляра `AddonPreferences` атрибут `bl_idname` возвращает мусорное значение (`'\x06'`); корректное имя — у класса. На работу аддона не влияет (`get_prefs()` ищет по `__package__`), но важно для тестов.
