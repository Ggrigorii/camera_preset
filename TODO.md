Состояние на момент записи: **v1.2.1**, проверено на Blender 5.2.3 LTS
(91 headless-проверка, 17 проверок установки, валидатор манифеста).

Ничего из этого ещё не реализовано — список составлен по итогам ручного теста

## 1. Риг: констрейнты не появляются при выборе пустышки

**Как воспроизводится.** Выбрать пустышку в поле **Rig** панели → камера не
привязывается, констрейнты не создаются, кадр не меняется.

**Причина.** В 1.2.1 поле Rig только *читает* существующую связь. Аддон не создаёт
`Damped Track` / `Track To` и не связывает камеру с пустышкой — предполагалось, что
риг собран вручную. Ожидание пользователя другое: выбрал пустышку — аддон сам собрал
связку.

**Варианты решения:**

| Вариант | Поведение | Плюсы | Минусы |
|---|---|---|---|
| **A. Кнопка `Bind Camera`** | Оператор создаёт пустышку (если нужно), `Damped Track` с `Track Axis = -Z`, `Up = Y`, опционально parent | явное действие, undo, не сюрприз | лишний клик |
| B. Автосоздание в `update` поля Rig | при выборе объекта сразу создаются констрейнты | «просто работает» | неявные изменения сцены, тяжело откатить, риск зацикливания update-колбэка |
| C. Проверка и предупреждение | панель пишет «у камеры нет констрейнта на этот объект» | безопасно | не решает задачу |

**Предпочтение:** A, плюс C как индикатор состояния. То есть оператор
`cam_preset.bind_rig` + строка статуса в панели.

**Требования к реализации:**

- не дублировать констрейнты: если у камеры уже есть `Damped Track`/`Track To` на
  этот объект — обновить ось, а не добавлять второй;
- `Track Axis = 'TRACK_NEGATIVE_Z'`, `Up = 'UP_Y'` (в 5.x у `Damped Track` по
  умолчанию `TRACK_Y` — это и есть главная причина «камера смотрит не туда»);
- parent ставить только по явному флагу, с корректным `matrix_parent_inverse`,
  чтобы кадр не прыгнул;
- `bl_options = {'REGISTER', 'UNDO'}`;
- работать только с объектами типа `CAMERA`;
- тест: после Bind камера следует за пустышкой, ось −Z, направление взгляда
  совпадает с направлением на цель.

**Открытый вопрос.** Нужен ли обратный оператор `Unbind` (снять констрейнты и
parent)? Пока считаю, что да — иначе аддон оставляет следы в сцене.

## 2. Кейфреймы и Smooth «ничего не делают» — убрать или переделать

**Как воспроизводится.** Тумблеры `Keyframe` и `Smooth` в панели не дают видимого
результата.

**Причина.** Оба режима пишут в трансформ камеры, а камера управляется констрейнтами —
значения игнорируются. В 1.2.1 для smooth это частично учтено (при заданном Rig
интерполируется риг), для `Keyframe` — нет: ключи ставятся на камеру.

**Мнение пользователя:** раздел не нужен, можно просто убрать.

**Варианты:**

| Вариант | Что делаем |
|---|---|
| **A. Убрать строку из панели** | тумблеры `Keyframe`/`Smooth` уходят из N-панели; остаются настройки в preferences (или удаляются совсем), код операторов не трогаем |
| B. Убрать полностью | удалить `cam_presets_keyframe` / `cam_presets_smooth`, ветки в `apply_state`/`start_smooth`, тесты и главу §5 SPEC |
| C. Починить | ключи ставятся на риг, smooth уже работает по ригу; добавить индикацию режима |

**Предпочтение:** B, если анимация не нужна в рабочем процессе. Пресеты — это статичные
кадры, а переходы между ними пользователь делает сам в таймлайне.

**Что учесть при удалении:** убрать `start_smooth`, `stop_smooth`, `_smooth_tick`,
таймеры, поля `cam_presets_smooth`/`cam_presets_keyframe`, ветки в `apply`, тесты
`test_smooth` / `test_keyframe`, упоминания в SPEC §5, §6.1, §9, §10 и в README.

**Если решим оставить (вариант C):** ключи должны ставиться на риг, если он задан;
для камеры без рига — на камеру; тумблеры показывать только когда есть что анимировать.

## 3. Passepartout в пресете

Добавить `passepartout_alpha` камеры в состояние пресета.

**API (проверено на 5.2.3):** `Camera.passepartout_alpha`, `FloatProperty`,
hard range `0.0 … 1.0`, default `0.5`. Значение `1.00` — полностью непрозрачная
рамка (то, что просил пользователь).

**План реализации:**

- поле пресета `passepartout_alpha: FloatProperty(default=1.0, min=0.0, max=1.0,
  subtype='FACTOR')`;
- добавить в `PRESET_FIELDS` (иначе не попадёт в JSON и в `defaults.json`);
- capture/apply в канале `OPTICS`;
- отображение в блоке деталей панели;
- обновить `defaults.json` генератором `tests/make_defaults.py` (значение `1.0`);
- тест: сохранить 1.0, изменить на 0.2, применить → снова 1.0.

**Открытый вопрос.** Passepartout — свойство камеры или сцены? Пользователь просит
хранить в пресете, значит камера. Но если в сцене несколько камер и они делят один
`passepartout`, поведение будет «как у камеры» — это и фиксируем.

## 4. Дополнительно к обсуждению

- **`Damped Track` vs `Track To`.** Сейчас поддерживаются оба (аддон не навязывает).
  Если Bind создаёт связку, надо решить, что ставим по умолчанию: `Damped Track`
  (без скрутки, стабильнее для камеры) или `Track To` (полный контроль осей).
  Предложение: `Damped Track` + `Up = Y`, а `Track To` — как опция в операторе.
- **Rig: сцена или пресет.** Сейчас поле Rig живёт на сцене, а имя рига пишется в
  каждый пресет. Если ригов несколько (разные камеры), стоит сделать Rig частью
  пресета и брать из него, а поле на сцене — только значение по умолчанию.
- **Пустышка как объект фокуса.** В текущем риге пустышка часто желанная цель DOF.
  Можно добавить в Bind опцию «использовать риг как `focus_object`».

## Критерии готовности v1.3

1. Выбор пустышки + `Bind Camera` создаёт связку; камера следует за пустышкой,
   направление взгляда — на неё.
2. Повторный вызов Bind не плодит дубликаты констрейнтов.
3. Раздел `Keyframe`/`Smooth` либо отсутствует в UI (вариант A/B), либо реально
   работает на риге (вариант C). Решение зафиксировать в SPEC.
4. `passepartout_alpha` сохраняется и восстанавливается, попадает в JSON и в
   `defaults.json`.
5. Прогон `tests\run_tests.bat` и `tests\install_check.py` — зелёный, число проверок
   обновлено в SPEC §10.
6. Версия поднята до 1.3.0, тег и коммит в репозитории.
